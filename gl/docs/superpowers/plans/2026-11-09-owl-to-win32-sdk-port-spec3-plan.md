# Spec #3 — Implementation Plan: General Ledger Reports

**Spec reference:** `gl/docs/superpowers/specs/2026-11-09-owl-to-win32-sdk-port-spec3-design.md`
**Date:** 2026-11-09
**Plan status:** Draft

**Paths:** relative to the repository root. Legacy sources are in `gl/src/` and `gl/header/`, the Crystal report files in `dbf/*.RPT`, new GL code in `gl/port/` and `gl/port/reports/`, and the new library in `report/` beside `win32fx/` and `cb4sqlite/`.

This plan carries out the Spec #3 design. If a milestone finds that the spec is wrong, **stop, fix the spec, then resume**.

**Read first, as in Spec #2.** Each milestone that ports an original report starts by re-reading its `.RPT` records (`python3 -I tools/rptdump.py dbf/GLTB.RPT`) and its handler, and checking the spec's §2.2 row. The finance set (M2–M4) is new function: its read task is the data — the real company's chart and balances (spec §2.5), migrated into a scratch database with `dbf2sqlite`.

## Milestone 0 — The portable core

**Goal:** a report can be built, laid out into pages and rendered as text on Linux, under test.

> **As built (2026-11-09; Linux only, Windows not yet built or run).**
> - **`report/`** (tasks 2–6): `include/report/Report.h` (the model, header-only), `Format.h`, `Layout.h`, `TextRender.h`, with `src/Format.cpp`, `Layout.cpp`, `TextRender.cpp`. `report.vcxproj` is generated by `genproj.py` (project 8), which now also writes `gl.sln` when `gl.sln` is named (`genproj.py . report gl.sln`). `common.props` puts `report\include` on every project's include path. Model details beyond spec §4.1: `Cell` carries cents or an integer or text (dates stay `yyyymmdd` until formatted); `Column::aligned()` overrides the type's default alignment; `RowKind::Slip` carries label/value pairs printed two to a line.
> - **Formatting** (task 4): the date rule is recorded in spec §4.3. `ToCents` rounds with `llround`.
> - **Layout** (task 5): as spec §4.2, with its "As built" note: side texts beside or above the company, block pagination, only notes wrap.
> - **`TextRender`** (task 6): `FixedMeasure` (100 × 200 twips per character and line) and `RenderText`, which prints rules as `-` and double rules as `=`, and vertical gaps as empty lines.
> - **`report_tests`** (task 7): `test_format.cpp`, `test_layout.cpp`, `test_golden.cpp` (16 cases); hand-written `report_tests.vcxproj` (project 9) like `gl_tests`'; `build_tests.sh` builds and runs it. The golden rendering is a three-page income-statement-style report, kept inline in the test as a raw string.
> - **`cb4sqlite::Query`** (task 8): `cb4sqlite/include/Query.h`, `src/Query.cpp`, in `cb4sqlite.h`; 6 cases in `cb4sqlite_tests/test_query.cpp`. `cb4sqlite.vcxproj` edited by hand (it is retargeted to v145); `cb4sqlite_tests.vcxproj` regenerated.
> - **Tools** (task 1): `tools/linux/README.md` documents `rptdump.py`, `report_tests` and the hand-written projects; `wincheck_all.sh` checks `report/src`.
> - *Windows (2026-11-10):* `report` and `report_tests` build `/W4 /WX` on Debug and Release x64 (VS 18, v145), and `report_tests` passes (16 cases, 118 assertions).

### Tasks

1. **`tools/rptdump.py`** (written with the spec): add a README entry in `tools/linux/README.md`.
2. **`report/` project** (spec §4): `report.vcxproj` (static library, `win32fx`'s property sheets), in `gl.sln`; `genproj.py` taught it if needed.
3. **Model** (`Report.h`, spec §4.1), including `Heading`, `Subtotal`, `Total` (single/double rule), `Note`, indents and slip mode.
4. **Formatting** (`Format.h`, spec §4.3): minus and parentheses styles. Check how the port's screens show dates and how `gl_btch.DATE`, `gl_btchd.DATE` and `gl_dist.DATE` are stored in the fixture and the real data; record the rule in spec §4.3.
5. **Layout** (`Layout.h`, spec §4.2).
6. **`TextRender`**, for golden tests and debugging.
7. **`report_tests`** (Catch2, top-level like `gl_tests`), the spec §11 cases; the Linux build alongside `build_tests.sh`, under ASan/UBSan.
8. **`cb4sqlite::Query`** (spec §7) and its `cb4sqlite_tests` cases.

### Exit criteria

- `report_tests` and `cb4sqlite_tests` pass on Linux; `wincheck_all.sh` covers `report/`.
- A golden rendering of a three-page test report, with a statement-style section, is committed and matches.

## Milestone 1 — Preview, Print and Printer Setup

**Goal:** any `rpt::Report` can be previewed and printed; new dialogs can be added.

> **As built (2026-11-10; built and run on Windows 11, VS 18, v145).** Where the tasks below differ, this note wins.
> - **`report/src/win32`** (tasks 1–4), in the `report` library, which now uses `win32fx` (the preview is an `MdiChild`):
>   - `Gdi.h` / `GdiMeasure.cpp`: `GdiMeasure` (printer IC, or the screen without a printer), `FontSet` (the four roles in twips: Arial 12 pt bold title, 9 pt body, 9 pt bold heading and bold; spec §14 Q2's proposal), `SetTwipsMapping` (`MM_ANISOTROPIC`, a twip per logical unit, y down) and `DrawPage`. A header the spec's file list lacked: the preview and printing share it.
>   - `PrinterSetup.h/.cpp`: the session printer (`PrintDlgW` `PD_RETURNDEFAULT` until chosen), `ShowPrinterSetup` (`PageSetupDlgW`, margins kept, orientation **disabled**: each report has its own, spec §4.6), `CurrentPageSetup` (A4 without a printer; margins widened to the unprintable edges), `PaperOrigin`, and the listener list that posts `kPrinterChanged` to open previews.
>   - `Print.h/.cpp`: `PrintReport`: `PrintDlgW` starting on the session printer in the report's orientation; the printer chosen there becomes the session printer; lay out again with a DC compatible with the chosen printer's; print the page range; a "Printing page n of m" window with Cancel (`SetAbortProc`), owner disabled meanwhile.
>   - `Preview.h/.cpp`: `OpenPreview` (a self-deleting MDI child), `PrintActivePreview`, `IsPreview`, and `PreviewPage` / `PreviewPageCount` / `CyclePreviewZoom` for tests and `/stress`. The page view is a child window with scroll bars, double-buffered; the wheel turns pages when the page fits.
> - **Found on Windows 11:** `PrintDlgW` shows the system print window ("Printing from Win32 application - Print"), which runs in `explorer.exe`; the calling thread waits in `PrintDlgW`. *Microsoft Print to PDF* asks for the file name in `StartDocW` ("Save Print Output As", in-process).
> - **`gl/port/reports/`** (task 5): `ReportContext.h/.cpp` (portable; `gl_tests`), `RunReport.h/.cpp` (Win32: `RunReport`, `CurrentReportContext`, `RunSampleReport`, `StressReports`), `ReportOptions.h/.cpp` (options dialogs) and `SampleReport.h/.cpp`: the engine's **test report** (portable; `gl_tests`), the chart of accounts grouped by type. With no original report ported yet, it is what the exit criteria are checked with: `gl.exe /samplereport`, and `/stress`. A builder that leaves `company` or `printedOn` empty gets the context's. `Report::printedOn` is the date only (Layout adds "Printed on").
> - **Resources** (task 6): IDs 20000–20999, used by nothing original (scanned: `gl_new.rc`, `gl.rc`, `gl/res/gl.rc`, `gl/header`, `include`, `gl/port`, `win32fx/include`), in `gl/port/PortIds.h` (plain `#define`s with an include guard: `rc.exe` reads it twice). `gl/res/port.rc` (hand-written, ASCII) has the sample report's options dialog. `prune_rc.py` `#include`s `PortIds.h` at the top of `gl.rc` and `port.rc` at the end, and has `MENU_EDITS` (rename / remove / insert-after, each matching exactly one item or stopping; empty until S3-M3; checked with a trial edit list). `prune_rc.py` runs on Windows with `CPP` set to Visual Studio's `clang-cpp.exe` and reproduces the committed `gl.rc` with only the two include lines added.
> - **Frame** (task 7): 2001 → Printer Setup (out of `kReportingCommands`); 3068 and the toolbar Print → `PrintActivePreview`, else the Reporting stub as before (the list is S3-M7); `CM_SAMPLE_REPORT` (20500) → the sample report.
> - **`trivial_dialog /selftest`** (task 8): links `report.lib`; GDI measuring on the screen, a 150-row layout on A4, every text inside the margins, page 1 drawn into a DIB, and a preview's PgDn / End / Home and zoom.
> - **`/stress`** opens the sample report (three copies) 25 times, paging at every zoom; it warms up twice, because one cached object created by the first preview is released during the second. Its message box now gives each step's count.
> - **Build files:** `genproj.py` lists `report`'s Windows sources, adds `report` to `gl`'s references and `gl/port/reports/` to `gl`'s file list, and sorts by the case-sensitive path (Windows' Python otherwise reorders). `gl_tests.vcxproj` and `build_tests.sh` compile `ReportContext.cpp` and `SampleReport.cpp`; `gl_tests` links `report`.
> - **Verification:** `gl.sln` and `trivial_dialog.sln` Debug and Release `/W4 /WX` clean; `cb4sqlite_tests` (77 / 1,498), `gl_tests` (48 / 690, 7 new) and `report_tests` (16 / 118) pass on both; `trivial_dialog /selftest /quiet`, `/checkres /quiet` and `/stress /quiet` exit 0 on both. The sample report (five copies, two pages) previewed, paged and printed to *Microsoft Print to PDF* from Debug and Release, driven through the Print and Save windows by UI Automation; the PDF's two pages match the preview. **Not checked:** a real printer; the Linux ASan/UBSan build of the new `gl_tests` sources; `wincheck_all.sh` over `report/src/win32`.

## Milestone 2 — Balances, F1, F2, year end

> **As built (2026-11-11; built and run on Windows 11, VS 18, v145).** Where the tasks below differ, this note wins.

> - **Fixture** (task 2): spec §9 "As built". 14 new accounts, 12 journals, an undistributed movement, a deleted line, prior-year and budget amounts. **The fixture was inconsistent:** 101000's and 102101's `CURR_BAL` left out voucher 100; fixed. > - **Options** (task 5): one dialog, `IDD_TB_OPTIONS` in `port.rc`, for both (F1 hides To and voucher lines); periods listed with their descriptions and "(current)". The choices are kept for the session (statics in `RunReport.cpp`).

> - **Wiring** (task 8): 6076 → F1, 1075 → F2; both out of `kReportingCommands`. Menu text unchanged.
> - **Timing** (task 9): F2 with voucher lines, periods 1–2, on the real company: the preview opens in about 0.3 s. The real data has only 13 lines, so this says little about a full year (spec R6 stays open until a larger year exists).
> - **Sample pages** (task 10): F1 and F2 (periods 1–7, voucher lines, landscape) printed to PDF from the fixture, and F2 from the real company. They showed truncated voucher-line text and dates ("10/15/20"): F2 widens Account and Description in landscape, and **the layout now prints `###` for a date that doesn't fit** (spec §4.2; `report_tests` case added). The house style (spec §14 Q2) is for the user to settle from these pages.
> - **`/stress`** also opens F1 and F2 (voucher lines) 25 times each; `/checkres` loads `IDD_TB_OPTIONS`.
> - **Not checked:** the Linux ASan/UBSan build of the new sources; the options dialog by hand (it was driven by messages).

## Cross-cutting

- **Per-port checklist** from the Spec #1 plan for every ported file.
- **Per-milestone gates:** `/W4 /WX` clean on Debug and Release x64; the milestone's tests pass on Linux (and Windows when built there); spec drift check; an entry under a "Spec #3" heading in `gl/docs/superpowers/plans/2026-05-10-progress.md`; the milestone's "As built" note here.
- **What not to do:**
  - Don't port AP, AR or fixed-asset reports.
  - Don't add parameters to the original reports (spec D17); the finance set has its options.
  - Don't write to the database from a report: `Query` is read-only. Only the layout screen and year end write.
  - Don't edit `gl/res/gl.rc` by hand: change `prune_rc.py` or `port.rc`.
  - Don't put account numbers in the statement code: they belong in the default layout only.

## Risks specific to the plan

| # | Severity | Risk | Mitigation |
|---|---|---|---|
| Q1 | Medium | M1 can't be checked on Linux beyond compiling. | Thin GDI code over the tested layout; the `/selftest` draw check; check M1 on Windows before M2's reports pile on it. |
| Q2 | Medium | The finance team rejects the default groupings or the style after the screens are built. | Sample pages after M2; the statements on real data at the end of M3, before M4. |
| Q3 | Medium | Hand-worked expected figures in the tests are themselves wrong. | Each statement has an independent cross-check in the tests: F4 balances, F4's net income = F3's YTD, F5's closing cash = F4's cash, F1's totals agree, F2's rows foot. |
| Q4 | Low | A fourth library in the solution and the Linux scripts. | Model it on `win32fx`; M0 task 2 sets up both builds first. |

## How to use this plan

M0 → M1, then M2 → M3 → M4 with M5 and M6 alongside, then M7 and M8. If the plan and the spec conflict, stop, edit the spec, recheck the plan, then continue.
