## 2026-11-11 — `/stress`: the intermittent "Chart of Accounts +1"

Branch: `claude/fervent-dhawan-1d583e`. The Debug `/stress` sometimes exited 1 with "Chart of Accounts +1".

### Found

- **Not a leak.** The extra object is always one USER object, never GDI. It appears once per process, at a time Windows chooses (0.4 to 4 s in, at open 6, 54 or 69 of the loop). It then stays. It landed in the master-data step once, and it did not appear in 50+ later runs. No window of the process is new when it appears. Cursors, icon queries, the system menu, `FlashWindow`, `WM_GETOBJECT` and real input to a stress dialog leave nothing behind once the dialog closes.
- A warm-up cannot absorb it, because its timing is random.

### Changed

- **Measurement only** (`gl/port/App.cpp`, `stressStep`): when a step reports growth, it runs a second time and the smaller reading is kept. A real per-open leak shows in both readings; this object can appear in only one. A forced second run of every step measures +0.

Branch: `port/m2-dbf2sqlite`.

### Done

- **Findings that changed the plan** (spec §4.5 rewritten, new §4.8):
  - `include/d4all.h` defines `S4MDX`, so the app used dBase IV **production `.mdx`** indexes, not `.ndx`/`.cdx`.
  - Header file names don't follow table names (8.3 era: `glaccts` → `db_accts.h`), so the generator's skip rule scans for `Data4(cb, "<table>")` / `Data4::open(cb, "<table>")` instead of checking file names.
  - Spec #1 touches 9 tables, not 4, so the default is to migrate every dBase table, detected by header so `ACCESS.PSW` is included.
  - The real tag expressions come from the source's `TAG4INFO` arrays (e.g. `GLACCTS`: `ACCOUNT`/`ACCOUNTS` = `account+dept`, `DEPT`, `TYPE`; `ACCESS.PSW`: `u` = `username`).
- **`dbf2sqlite_core`:**
  - DBF reading via shapelib, with an open hook for non-`.dbf` names.
  - `.mdx` tag reader based on the CodeBase `S4MDX` structures, validating every slot.
  - Code page → UTF-8, with widening instead of truncation.
  - dBase key-expression translator: fields, `+`, `UPPER`, `DTOS`, `STR`.
  - Migration in one transaction per table, with `_rowid` = record number and deleted flags kept, read-back verification, and atomic `<out>.tmp` → rename.
  - Header generator with a committed golden output.
- **`dbf2sqlite.exe`:** CLI per spec §4.5 plus `--codepage`, `--headers-out` and `--headers-check`; `wmain` with UTF-8 arguments on Windows.
- **Fixtures:** `dbf2sqlite_core/test/make_fixtures.py`, a deterministic generator, writes `fixtures/{company,bad,corrupt_dbf,corrupt_mdx}`.
- **Tests:** 9 new Layer-2 cases in `cb4sqlite_tests/test_dbf2sqlite.cpp`.
  - All 6 sample tables migrate and read back through the unchanged `db_accts.h`, `db_acces.h` and `db_dept.h`. That includes cp1252 → UTF-8, the deleted record, blank values, tag order, and `STR()`/`UPPER()` keys.
  - Exit codes 1, 2 and 4 are covered, as are `--force`, `--table` and widening.
  - The generated `db_accessm.h` matches the golden file byte for byte, re-running doesn't change it, and it is compiled into the tests and run against migrated data.

### Verification

- **Linux, g++** with `-Werror` and ASan + LSan + UBSan: **All tests passed (774 assertions in 44 test cases)**; also in 2 random orders, and run from `cb4sqlite_tests/`.
- **CLI** on the fixtures: company → exit 0; bad → exit 4 with no output file; corrupt `.mdx` / truncated `.dbf` → exit 2; unknown argument → exit 1. Generating into `include/` left the hand-written `db_accts.h` byte-identical.
- **`_WIN32` paths:** `Encoding.cpp` and `main.cpp` (`wmain`) syntax-check clean. `DbfFile.cpp` / `test_dbf2sqlite.cpp` can't be checked that way on Linux (libstdc++ has no wide `ifstream(path)` when `_WIN32` is faked), so they still need the MSVC build.

## 2026-11-06 — M1 `cb4sqlite` shim core

Branch: `port/m1-cb4sqlite`.

### Done

- **Ground truth changed:** the original CodeBase headers in `include/` (`d4data.hpp`, `d4defs.h`, `e4expr.h`) were read alongside every shim call in the five Spec #1 sources. Several plan/spec assumptions were wrong, and the implementation follows CodeBase instead. Spec §4.2/§4.3/§4.4/§4.6 are rewritten and **spec §4.7 lists each deviation**. The biggest:
  - `r4eof` is 3, not -22.
  - CodeBase's record-buffer write model, where changes are written on `flush()` or the next move.
  - `appendStart → assign → append`.
  - Partial-key `seek`.
  - Deleted records stay visible until `pack()`.
  - `_cb_tags.key_expr` plus a new `_cb_fields` table.
- **Implemented:** `Code4`, `Data4`, `Field4` (+ Windows `SetField`/`AssignField`), `Date4`, `Relate4set`, and `Schema` (`createTable`/`createTag`, shared with M2). The M0 `stub_impl.cpp` is gone.
- **Tests:** 35 Catch2 cases in `cb4sqlite_tests/`, plus 2 Windows-only cases in `test_field4_win32.cpp`. They include `test_legacy_headers.cpp`, which drives the unchanged `db_accts.h` (all 44 fields), `db_acces.h` and `db_dept.h` through the shim; that covers plan risk P1. `parse_smoke.cpp` now calls every shim method the Spec #1 screens use.
- **`cb4sqlite/README.md`:** semantics, the method-coverage table, and the compile-only stub list (plan M1 exit criterion 2).
- **`legacy_headers_begin.h`** now also silences C4459 / `-Wshadow`: the headers' `Code4 *cb` parameters hide the global `cb`.
- `db_btchd.h` now compiles too (it needed `Field4::trim()`). `db_arbtc.h` still needs `Field4memo`.

### Verification

- **Linux, g++** with `-Wall -Wextra -Wpedantic -Wshadow -Wconversion -Wsign-conversion -Werror` and AddressSanitizer + LeakSanitizer + UBSan: **All tests passed (613 assertions in 35 test cases)**. Also passes in 3 random orders.
- **`_WIN32` code paths** (`Field4_win32.cpp`, the wide `Code4::open`, `test_field4_win32.cpp`, `parse_smoke.cpp`) syntax-checked with g++ against a stand-in `<Windows.h>`.
- Two bugs were caught by the tests while writing them and fixed:
  - Table opens failed: an aliasing bug in `loadTableInfo`.
  - An abandoned append could overwrite the current record.
