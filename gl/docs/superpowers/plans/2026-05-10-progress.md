## 2026-11-06 — M1 `cb4sqlite` shim core

Branch: `port/m1-cb4sqlite`.

### Done

- **Ground truth changed:** the original CodeBase headers in `include/` (`d4data.hpp`, `d4defs.h`, `e4expr.h`) were read alongside every shim call in the five Spec #1 sources. Several plan/spec assumptions were wrong, and the implementation follows CodeBase instead. Spec §4.2/§4.3/§4.4/§4.6 are rewritten and **spec §4.7 lists each deviation**. The biggest:
  - `r4eof` is 3, not -22.
  - CodeBase's record-buffer write model, where changes are written on `flush()` or the next move.
  - `appendStart → assign → append`.
  - Partial-key `seek`.
  - Deleted records stay visible until `pack()`.
  - `_cb_tags.key_expr` plus a new `_cb_fields` table.
- **Implemented:** `Code4`, `Data4`, `Field4` (+ Windows `SetField`/`AssignField`), `Date4`, `Relate4set`, and `Schema` (`createTable`/`createTag`, shared with M2). The M0 `stub_impl.cpp` is gone.
- **Tests:** 35 Catch2 cases in `cb4sqlite_tests/`, plus 2 Windows-only cases in `test_field4_win32.cpp`. They include `test_legacy_headers.cpp`, which drives the unchanged `db_accts.h` (all 44 fields), `db_acces.h` and `db_dept.h` through the shim; that covers plan risk P1. `parse_smoke.cpp` now calls every shim method the Spec #1 screens use.
- **`cb4sqlite/README.md`:** semantics, the method-coverage table, and the compile-only stub list (plan M1 exit criterion 2).
- **`legacy_headers_begin.h`** now also silences C4459 / `-Wshadow`: the headers' `Code4 *cb` parameters hide the global `cb`.
- `db_btchd.h` now compiles too (it needed `Field4::trim()`). `db_arbtc.h` still needs `Field4memo`.

### Verification

- **Linux, g++** with `-Wall -Wextra -Wpedantic -Wshadow -Wconversion -Wsign-conversion -Werror` and AddressSanitizer + LeakSanitizer + UBSan: **All tests passed (613 assertions in 35 test cases)**. Also passes in 3 random orders.
- **`_WIN32` code paths** (`Field4_win32.cpp`, the wide `Code4::open`, `test_field4_win32.cpp`, `parse_smoke.cpp`) syntax-checked with g++ against a stand-in `<Windows.h>`.
- Two bugs were caught by the tests while writing them and fixed:
  - Table opens failed: an aliasing bug in `loadTableInfo`.
  - An abandoned append could overwrite the current record.
